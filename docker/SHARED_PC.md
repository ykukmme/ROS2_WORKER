# Ubuntu에서 처음부터 실행하기

공개 Docker 이미지를 다운로드하고 AI WORKER를 연결해 초기 설정과 첫 분류를 수행하는 순서다.
아래 명령은 별도 표시가 없으면 **Ubuntu PC의 일반 터미널**에서 실행한다.
컨테이너 안에 들어가 패키지를 설치하거나 ROS2 환경을 직접 source할 필요는 없다.

| 항목 | 이 가이드의 기준 |
|---|---|
| PC | Ubuntu Linux / x86_64(amd64) |
| Docker 이미지 | `ghcr.io/ykukmme/ros2-worker:jazzy` |
| 이미지 내부 환경 | Ubuntu 24.04 / ROS2 Jazzy / Python 3.12 / CPU |
| 기본 제어 | 공식 Cyclo MoveL 인터페이스의 왼팔 |
| 분류 대상 | YOLO가 서로 다른 두 종류로 인식하는 물건 |
| 목적지 | 서로 다른 두 색의 테이프로 만든 빈 사각 구역 각 1개. 색 지정 없이 자동 인식 |
| 저장 위치 | Docker 볼륨 `ros2-worker-data` |

**1~4단계는 로봇 없이도 가능하다. 실제 초기 설정과 분류에는 5~7단계의 로봇·카메라·작업 공간 준비가 필요하다.**
GitHub 로그인·Docker 로그인·로컬 이미지 빌드·호스트 ROS2/Python 설치는 일반 실행에 필요 없다.

## 1. PC에서 Docker가 실행되는지 확인

터미널을 열고 실행한다:

```bash
uname -m
docker version
docker info --format '{{.OSType}}'
```

- `uname -m`: `x86_64`가 나오는지 확인한다. 이 공개 이미지는 ARM/Jetson용이 아니다.
- `docker version`: Client와 Server 정보가 모두 나와야 한다.
- 마지막 명령: `linux`가 나와야 한다.

`docker: command not found`, `permission denied`, `Cannot connect to the Docker daemon`이면 먼저 PC 담당자에게 Docker 설치·실행·현재 계정의 사용 권한을 확인한다.
현재 계정으로 위 명령이 성공한 뒤 다음 단계로 진행한다.
설치가 필요한 경우 [Docker의 Ubuntu 설치 안내](https://docs.docker.com/engine/install/ubuntu/)와 [사용 권한 안내](https://docs.docker.com/engine/install/linux-postinstall/)를 따른다.
기존 공용 PC의 Docker 설치나 권한을 이 프로그램이 자동 변경하지는 않는다.

## 2. Docker 이미지 다운로드

```bash
docker pull ghcr.io/ykukmme/ros2-worker:jazzy
```

처음에는 여러 레이어를 다운로드하고 압축을 해제한다. 네트워크와 수 GB의 Docker 저장 공간이 필요하다.
마지막에 다음 중 하나가 표시되면 다운로드가 끝난 것이다:

```text
Status: Downloaded newer image for ghcr.io/ykukmme/ros2-worker:jazzy
Status: Image is up to date for ghcr.io/ykukmme/ros2-worker:jazzy
```

이미지에 프로그램 코드·ROS2·공식 메시지·기본 형상 자산·YOLO·기본 가중치가 포함된다.
일반 실행에서는 `pip install`, `colcon build`, `bash scripts/worker.sh build`를 실행하지 않는다.

## 3. 실행기 받기

### 처음 다운로드하는 PC

Git이 있는지 확인한다:

```bash
git --version
```

Git이 있으면 다음을 실행한다:

```bash
cd ~
git clone https://github.com/ykukmme/ROS2_WORKER.git
cd ROS2_WORKER
```

이후 `bash worker.sh ...` 명령은 이 폴더에서 실행한다.
Git clone은 실행기와 문서를 받는 과정이고, 2단계의 Docker pull은 실행 환경 전체를 받는 과정이다.

### 이미 ROS2_WORKER 폴더가 있는 PC

새로 clone하지 않고 기존 폴더에서 최신 실행기와 문서를 받는다:

```bash
cd ~/ROS2_WORKER
git pull
```

다른 위치에 clone했다면 `cd` 경로를 실제 저장소 위치로 바꾼다.
Git이 없으면 문서 끝의 **Git 없이 실행기만 받기**를 사용한다. 두 다운로드 방법 중 하나만 선택한다.

## 4. 이미지 안의 프로그램과 가중치 확인

기존 호스트 폴더의 설정을 볼륨으로 가져올 경우에는 이 검사로 새 볼륨에 파일을 만들기 전에 [데이터 가져오기](../DOCKER.md)의 `import-data` 절차를 수행한다.
이미 Docker 볼륨에 저장한 설정은 그대로 재사용한다.

```bash
bash worker.sh check
```

정상 출력에는 다음 내용이 포함된다:

```text
ROS2: jazzy Python: 3.12... Dependencies/model OK; device: cpu
```

이 검사는 이미지 내부 ROS2·Python 의존성과 내장 가중치를 확인한다. 로봇 명령을 보내지 않는다.
통과해도 카메라 연결이나 실제 집기까지 확인한 것은 아니다.
실행 중 만들어지는 Ultralytics 설정 안내는 오류가 아니다.

기본 모델 경로나 추론 장치를 직접 입력할 필요는 없다. 공개 CPU 이미지는 자동으로 CPU를 사용한다.
메뉴에서는 저장한 커스텀 모델이 있다면 그 경로를 우선 사용한다. 경로 오류가 발생하면 [고급 설정](../ADVANCED_SETUP.md)을 확인한다.
`check`는 내장 모델 파일의 존재와 라이브러리 로딩을 확인하며, 실제 인식 결과는 초기 스캔에서 확인한다.

## 5. 공식 로봇 제어 환경과 카메라 준비

장비에서 사용하던 공식 절차로 다음을 실행한다. 이미 실행 중인 노드는 중복 실행하지 않는다.

| 준비 항목 | 확인할 내용 |
|---|---|
| 공식 bringup·MoveL 제어기 | 로봇이 정상 기동하고 기존 조그 기능을 사용할 수 있다 |
| RGB-D 카메라 | RGB·색 영상에 정렬된 깊이·CameraInfo가 계속 발행된다 |
| TF | 카메라 좌표와 로봇 기준 좌표·제어 TCP가 정확히 연결돼 있다 |
| 관절 피드백 | `/joint_states`에 팔·그리퍼 상태가 들어온다 |
| 로봇 모델 | 실제 그리퍼 형상·장착·TCP가 반영된 `robot_description`을 읽을 수 있다 |

공식 제어 환경은 로봇 내부 또는 기존 제어 PC에서 실행될 수 있다.
**이 분류 이미지는 공식 하드웨어 드라이버·Cyclo 제어기를 대신 기동하지 않는다.**
장비 모델과 설치 구성에 따라 bringup 명령이 달라지므로 해당 장비의 기존 운용 절차를 사용한다.

처음 생성하는 설정의 기본 연결은 다음과 같다:

| 항목 | 기본값 |
|---|---|
| RGB | `/camera/color/image_raw` |
| 정렬된 깊이 | `/camera/aligned_depth_to_color/image_raw` |
| CameraInfo | `/camera/color/camera_info` |
| 로봇 기준·제어 좌표 | `base_link` |
| 제어기 노드 | `/ai_worker_movel_controller` |
| 왼팔 MoveL | `/l_goal_move` |
| 그리퍼 명령 | `/leader/joint_trajectory_command_broadcaster_left/raw_joint_trajectory` |
| 관절 피드백·그리퍼 관절 | `/joint_states` / `gripper_l_joint1` |
| 제어 TCP | 제어기의 `l_gripper_name` 파라미터에서 확인 |
| 로봇 모델 | `/robot_state_publisher`의 `robot_description` |

카메라가 여러 개라면 집기에 사용할 카메라의 RGB·정렬된 깊이·CameraInfo 한 세트를 지정한다.
서로 다른 카메라의 영상이나 좌표계를 섞지 않는다.
기본 토픽이나 좌표계가 현장과 다르면 [실물 연결](../ai_worker_sorting/LIVE_ROBOT.md)과 [고급 설정](../ADVANCED_SETUP.md)에 따라 설정을 맞춘다.
메뉴가 모든 장비의 토픽 이름을 자동으로 찾아 바꾸는 것은 아니다. 기존 설정이 있으면 해당 설정을 이어받는다.
일반 RGB 웹캠만 있는 상태에서는 이 실물 집기 절차를 진행하지 않는다.

## 6. 테이블과 물건 배치

1. 같은 수평 테이블 위에 **서로 뚜렷하게 다른 두 색의 테이프로 사각형을 각각 1개씩** 만든다. 색 이름은 입력하지 않는다.
2. 각 사각형의 네 변을 끊김 없이 닫고, 두 구역이 겹치지 않게 한다. 내부는 비워 둔다.
3. 두 종류의 물건은 목적 구역 밖에 놓는다. 첫 검증은 종류별 1개씩 준비하면 된다.
4. 서로 붙이거나 겹치지 않고 물건 전체·깊이·두 테이프 경계가 카메라에 보이게 한다.
5. 집기와 배치 위치 모두 실제 팔이 도달할 수 있는 범위에 둔다.

두 종류는 **YOLO의 서로 다른 인식명**으로 구분돼야 한다.
사람이 보기에 다른 물건이어도 YOLO가 같은 인식명으로 판단하면 두 종류로 나눌 수 없다.
기본 모델이 구분하지 못하는 물건은 해당 종류를 학습한 가중치가 필요하다. [커스텀 모델 안내](../ADVANCED_SETUP.md)를 따른다.

두 종류 모두 같은 하향 그리퍼 방향으로 집을 수 있어야 한다.
물건 치수·그리퍼 길이를 직접 입력하지는 않지만, 카메라의 형상 관측과 정확한 URDF·TF가 필요하다.
구역 크기가 부족하거나 깊이를 얻지 못하면 프로그램이 준비를 거부한다.
영상의 색 분포에서 테두리 색을 자동으로 찾으므로 특정 색 목록으로 제한하지 않는다.
검정·흰색·회색 테이프는 배경과 대비가 충분해야 한다. 매우 비슷한 두 색·배경에 묻히는 색·가려진 테두리는 거부한다.
닫힌 구역 후보가 세 개 이상이면 임의로 두 개를 고르지 않는다. 사용하지 않을 사각 테두리를 시야 밖으로 옮긴다.

## 7. ROS2 통신 설정

Ubuntu PC와 공식 로봇 제어 환경이 서로 통신 가능한 네트워크에 있어야 한다.
ROS2 Jazzy·domain·현장의 middleware 설정과 PC/로봇 시간을 맞춘다.
장비를 연결하는 초기 확인에는 같은 유선 네트워크를 사용하는 구성이 단순하다.

기본은 domain `0` / Fast DDS다. 현장도 이 값을 사용하면 추가 입력 없이 진행한다.
다른 설정이면 **메뉴를 실행할 터미널에서**, 실제 로봇 값을 확인해 지정한다:

```bash
# 0은 로봇의 실제 domain 번호로 바꾼다.
export ROS_DOMAIN_ID=0
```

로봇이 Cyclone DDS를 사용하는 구성일 때는 다음도 지정한다:

```bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
```

Fast DDS로 명시하려면 다음을 사용한다:

```bash
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
```

두 middleware 중 현장에 맞는 하나를 선택한다. 새 터미널에서는 필요한 값을 다시 지정한다.
PC 시간을 확인하려면 `timedatectl status`를 사용한다.
방화벽·네트워크 경로·별도 DDS 프로파일은 현장 설정을 따른다. 실행기는 Linux host network/IPC를 사용한다.

## 8. 메뉴 열기

팔을 작업물에서 떨어뜨리고, 그리퍼를 빈 상태로 둔다. 카메라를 가리지 않고 위로 움직일 여유가 있어야 한다.
특정 관절 각도의 고정 준비 자세나 미리 열린 그리퍼를 요구하지 않는다.

```bash
bash worker.sh
```

실행 정보에 `IMAGE=ghcr.io/ykukmme/ros2-worker:jazzy`와 실제 domain·볼륨 이름이 나오는지 확인한다.
이어서 다음 메뉴가 표시된다:

```text
AI WORKER 분류 — 설정: 없음
1 초기 설정 / 2 물건·구역 확인 / 3 분류 시작 / 4 작업 상태 / 5 작업 취소 / 6 연결 검사 / 0 종료
선택:
```

번호를 입력하고 Enter를 누른다. 메뉴가 자체 인식·분류 노드를 관리한다.
메뉴를 여는 것만으로 실제 분류 동작이 시작되지는 않는다.
대화형 터미널에서 실행하고 작업 중 해당 터미널을 유지한다.

`설정: 있음`이고 장비·물건 종류·교시가 그대로라면 9단계를 생략하고 10단계로 진행한다.
로봇 없이 메뉴 진입만 확인하는 경우 `0`으로 종료하면 된다.

## 9. 최초 한 번 초기 설정

메뉴에서 `1`을 입력한다. 저장된 설정을 덮어쓸 때만 새로 지정할지 묻고, 계속하려면 `y`를 입력한다.
이 과정의 프로그램은 관측과 기록만 수행한다. **자세를 움직이는 작업은 기존 로봇 조그 기능으로 직접 수행한다.**

### 9-1. 작업 범위 입력

저장된 범위나 `WORKER_WORKSPACE`가 없으면 다음을 묻는다:

```text
작업 범위 xmin,xmax,ymin,ymax,zmin,zmax []:
```

로봇 기준 좌표의 허용 범위를 **미터(m)** 단위 숫자 6개로, 쉼표로 구분해 입력한다.

| 순서 | 뜻 |
|---|---|
| `xmin,xmax` | 허용하는 X 좌표의 최솟값·최댓값 |
| `ymin,ymax` | 허용하는 Y 좌표의 최솟값·최댓값 |
| `zmin,zmax` | 허용하는 Z 좌표의 최솟값·최댓값 |

카메라 픽셀이나 물건 치수를 입력하는 항목이 아니다.
물건·두 목적 구역·상향 이송 경로·작업 중 복귀할 위치가 들어가는 **현장에서 확인한 범위**를 사용한다.
좌표축과 허용 범위를 모르면 장비 담당자의 검증된 값을 확인한다. 예시 숫자를 그대로 넣거나 임의로 크게 지정하지 않는다.
최초 설정이 저장되면 다음 실행부터 재사용한다.

### 9-2. 두 종류와 빈 구역 스캔

```text
두 종류의 물건 전체와 빈 테이프 구역을 보이게 놓고 Enter를 누르세요.
```

6단계의 배치를 확인하고 Enter를 누른다. 카메라·인식 결과를 기다린 뒤 두 종류를 등록한다.
이후 교시가 끝날 때까지 **물건·테이블·카메라의 위치를 바꾸지 않는다.**

### 9-3. 첫 번째 종류의 집기 자세 기록

```text
첫 번째 종류(현재 인식명: ... )를 집을 자세를 지정한 뒤 Enter:
```

화면의 현재 인식명을 보고 해당 물건을 확인한다.
기존 조그로 그 물건을 집을 때의 TCP 중심·높이·하향 방향을 맞춘 뒤, 메뉴 터미널에서 Enter를 누른다.
물건을 들어 옮기는 단계가 아니다. 원래 물건 위치를 유지한다.

RH-P12-RN의 형상·장착·TCP가 URDF·TF에 정확히 반영됐다는 전제에서 그리퍼 길이를 계산한다.
빈 테이블에 그리퍼 최저점을 맞추는 교시는 수행하지 않는다.
모델이나 STL 자산을 읽을 수 없으면 교시를 중단하므로 [고급 설정](../ADVANCED_SETUP.md)을 확인한다.

### 9-4. 두 번째 종류의 집기 자세 기록

```text
두 번째 종류(현재 인식명: ... )를 집을 자세를 지정한 뒤 Enter:
```

두 번째 물건으로 옮겨 같은 방식으로 맞추고 Enter를 누른다.
**첫 번째 종류를 교시한 그리퍼 방향을 유지한다.**
종류별 집기 높이를 따로 기록하므로 두 종류의 자세 지정이 각각 한 번 필요하다.

### 9-5. 팔을 작업물에서 떨어뜨리고 저장

```text
팔을 작업물에서 떨어뜨리세요. 집기 방향을 유지한 뒤 Enter:
```

물건과 카메라 시야에서 팔을 피하고, 위로 이동할 여유가 있는 위치로 옮긴다.
그리퍼는 비어 있어야 하며 교시한 방향은 유지한다. Enter를 누른다.

```text
설정을 저장했습니다. 다음부터 재사용합니다.
```

이 문구가 나오면 초기 설정이 끝난 것이다. 메뉴에 `설정: 있음`이 표시된다.
저장됐다고 해서 실제 집기 성공까지 확인한 것은 아니다.

## 10. 연결과 자동 배정 확인

초기 설정이 저장된 뒤 메뉴에서 `6`을 선택한다.

```text
연결 검사 통과. 움직임이나 집기 성공을 확인한 것은 아닙니다.
```

RGB·정렬된 깊이·CameraInfo·관절 피드백·TF·제어기 계약을 확인한다. 명령은 보내지 않는다.
처음 설정이 없는 상태에서는 `6`보다 `1 초기 설정`을 먼저 수행해야 한다.

이어서 `2 물건·구역 확인`을 선택한다. 두 목적 구역은 비어 있어야 한다.

```text
인식한 두 종류와 목적 구역을 확인했습니다.
첫 번째 종류 → 구역 ID
두 번째 종류 → 구역 ID
```

구역은 `zone_1`·`zone_2`로 표시되고 감지 색과 화면의 위·아래 또는 왼쪽·오른쪽 위치를 함께 보여준다.
대화형 터미널에서는 색상 견본도 표시한다. `#ff8000` 같은 값은 감지한 RGB 색상이며 직접 입력하는 값이 아니다.
같은 메뉴 안에서 재확인할 때에는 구역의 이전 위치를 기준으로 번호를 유지한다.
어느 종류를 어느 색으로 보낼지는 프로그램이 자동 배정한다.
이 단계는 인식·배정 확인이며 팔을 움직이지 않는다.

## 11. 첫 실제 분류

1. 첫 시험은 종류별 1개씩, 두 목적 구역이 빈 상태에서 진행한다.
2. 팔이 작업물에서 떨어져 있고 그리퍼가 비었는지 확인한다.
3. 메뉴에서 `3 분류 시작`을 선택한다. 시작 직전 인식과 구역 배정을 다시 확인한다.

```text
처리 개수 [기본 2, 모두 처리 0]:
```

첫 시험에는 `2`를 입력하거나 Enter를 눌러 기본값 2개를 사용한다.
이후 남은 대상 전체를 처리하려면 `0`을 지정한다.

```text
실제 분류를 시작할까요? [y/N]:
```

진행하려면 `y`와 Enter를 누른다. **이 확인 뒤 실제 로봇 동작을 시작할 수 있다.**
Enter만 누르거나 `y` 이외의 값을 입력하면 시작하지 않는다.
물건·모델·좌표의 실제 일치는 현장에서 확인해야 한다.

작업 중에는 상태와 배치 완료 개수를 표시한다.

| 상태 | 뜻 |
|---|---|
| `QUEUED` / `RUNNING` | 작업 대기 또는 실행 중 |
| `SUCCEEDED` | 프로그램이 작업 완료로 판정 |
| `FAILED` | 작업 실패. 실패 원인과 실제 장비 상태를 확인 |
| `CANCELED` | 취소 처리된 종료 상태. 실제 장비 상태도 확인 |

물건을 각 목적 구역에 놓았는지와 그리퍼가 비었는지 직접 확인한다.
처리 개수를 지정한 경우에는 그 개수만큼 끝나도 `SUCCEEDED`가 될 수 있다. 테이블 전체가 비었다는 의미는 아니다.
기본 이동은 천천히 설정돼 있지만 실제 최고 속도를 보장하는 하드웨어 제한을 대신하지는 않는다.

## 12. 상태 확인·취소·종료

| 상황 | 조작 |
|---|---|
| 자동 갱신 화면에서 취소 | `c` 입력 후 Enter |
| 자동 갱신 화면에서 메뉴로 돌아가기 | Enter |
| 메뉴에서 현재 작업 확인 | `4` |
| 메뉴에서 취소 요청 | `5` |
| 실제 정지·작업 종료를 확인한 뒤 메뉴 종료 | `0` |

Enter로 메뉴에 돌아가도 실행 중인 작업은 계속된다.
취소는 요청이므로 종료 상태와 실제 장비 정지를 함께 확인한다.
시작 응답이 시간 초과되면 `3`을 다시 누르지 말고 `4`에서 상태를 확인한다.
상태를 확인할 수 없거나 장비가 계속 움직이면 현장 비상정지 절차를 따른다.

`Ctrl+C`, 터미널 닫기, `docker stop/kill`을 로봇 정지 수단으로 사용하지 않는다.
메뉴는 실행 중이거나 상태가 불명확하면 정상 종료를 보류할 수 있다.
작업 실패 후 내부 노드를 종료할지 묻는 경우 실제 정지를 확인한 뒤에만 답한다.

정상 종료 후 컨테이너는 제거되지만 Docker 이미지와 설정 볼륨은 남는다.

## 13. 다음 묶음과 다음 날 다시 실행

**한 번 시작한 분류 세션은 재사용할 수 없다.** 같은 메뉴에서 다시 `3`만 누르는 방식으로 다음 묶음을 시작하지 않는다.

1. 이전 작업의 종료 상태와 실제 장비 정지를 확인한다.
2. 메뉴의 `0`으로 종료한다.
3. 목적 구역의 이전 물건을 치우고 두 구역을 비운다. 새 분류 대상은 구역 밖에 놓는다.
4. 공식 제어기·카메라가 계속 정상 실행 중인지 확인한다.
5. 필요한 domain·middleware를 같은 터미널에 지정하고 다음을 실행한다:

```bash
cd ~/ROS2_WORKER
bash worker.sh
```

6. 장비·두 종류·교시가 그대로면 `1 초기 설정`을 반복하지 않는다. `6` → `2` → `3` 순서로 진행한다.

새로운 묶음을 위해 구역을 비우는 작업과 물건 보충은 이전 작업이 실제로 끝난 뒤에 한다.
물건 종류·집기 자세·그리퍼·장착·카메라 보정·작업 범위가 바뀌면 다시 초기 설정한다.
같은 종류라도 크기·놓인 자세가 기존 교시와 관측 범위를 벗어나면 새로 검증한다.
카메라·테이블·로봇 기준 관계를 바꾼 경우 TF 보정도 먼저 확인한다.

## 14. 프로그램 업데이트

실제 장비 정지와 작업 종료를 확인하고 메뉴를 닫은 뒤 실행한다:

```bash
cd ~/ROS2_WORKER
git pull
bash worker.sh update
bash worker.sh
```

- `git pull`: 실행기와 문서를 갱신한다.
- `bash worker.sh update`: 최신 공개 이미지를 받는다.
- `bash worker.sh`: 새 이미지로 메뉴를 연다.

Git만 갱신하면 이미지 안의 프로그램은 바뀌지 않는다.
일반 `bash worker.sh`는 캐시한 이미지를 사용하며 자동 업데이트하지 않는다.
`update`는 설정 볼륨을 초기화하지 않고, 실행 중인 기본 컨테이너가 있으면 거부한다.

## 15. 문제가 생겼을 때

| 증상 | 확인·조치 |
|---|---|
| Docker 명령 자체가 실패 | 1단계의 Docker 실행·사용 권한 확인 |
| `denied` / `unauthorized` / 다운로드 실패 | PC 네트워크·GHCR 접근을 확인한다. 공개 이미지이므로 GitHub 로그인부터 추가하지 않는다 |
| `bash: worker.sh: No such file` | 저장소 안에서 실행했는지 확인. `cd ~/ROS2_WORKER` |
| `ModuleNotFoundError` | 호스트 Python으로 직접 실행했는지 확인하고 `bash worker.sh`를 사용한다. 컨테이너 안에서도 발생하면 `check` 결과와 로그를 확인 |
| 저장한 YOLO 가중치 경로 오류 | 가중치가 컨테이너에서 보이는 경로인지 확인. [커스텀 모델 안내](../ADVANCED_SETUP.md)를 따라 볼륨에 배치 |
| `Local image missing: ros2-worker:...` | 이전 `WORKER_IMAGE`·`WORKER_ROS_DISTRO` 지정 여부 확인. 기본 공개 이미지를 쓸 때만 해당 변수 해제 |
| `container name ... already in use` | 기존 메뉴·컨테이너와 장비 상태 확인. 실행 중인 장비의 컨테이너를 강제로 제거하지 않는다 |
| `설정: 없음` | 처음 실행이거나 다른 볼륨 사용 여부 확인. 최초에는 `1`로 설정 |
| `6`에서 설정 파일 없음 | `1 초기 설정` 저장을 먼저 완료 |
| 카메라·인식 결과를 계속 기다림 | 공식 카메라 발행·domain·토픽·네트워크·시각 확인. `calibration.log` 확인 |
| `Exactly two ... classes` | YOLO가 서로 다른 두 인식명으로 구분하는지, 다른 종류가 화면에 추가로 잡히는지 확인 |
| `Exactly two closed tape rectangles required` | 닫힌 사각 테두리가 정확히 두 개인지, 가림·경계 끊김·배경 대비를 확인 |
| `Tape colors are too similar` | 서로 충분히 구분되는 두 테이프 색으로 바꾼다. 같은 색 두 구역은 사용하지 않는다 |
| `Start with empty destination zones` | 작업이 끝난 뒤 두 목적 구역의 물건을 치우고 다시 준비 |
| `ZONE_TOO_SMALL` / `ZONE_FULL` | 목적 구역 여유 공간 확인. 작업이 끝난 뒤 구역 재배치·비우기 |
| `Session already used` | 13단계에 따라 이전 작업 종료 확인 후 메뉴 종료·새 세션 시작 |
| `stale` / 시각 오류 | PC·로봇 시각, 실제 영상 갱신, TF 갱신 확인 |
| 모델·STL·TCP·제어기 계약 오류 | 실제 로봇 모델과 컨테이너 자산·기본 연결 확인. [고급 설정](../ADVANCED_SETUP.md) 참고 |
| 집기 방향·높이·범위 오류 | 실제 좌표·그리퍼 방향·교시를 확인. 제한값을 임의로 늘려 통과시키지 않는다 |

기본 공개 이미지로 되돌릴 때만, 메뉴를 닫고 이전 이미지 선택 변수를 해제한다:

```bash
unset WORKER_IMAGE WORKER_ROS_DISTRO
bash worker.sh check
```

로그는 Docker 볼륨의 `/data/config/menu-logs/`에 있다.
다음 명령은 **Ubuntu 호스트 터미널에서** 실행하며 로그만 읽는다:

```bash
docker run --rm --pull never --network none --user 1000:1000 \
  --mount type=volume,src=ros2-worker-data,dst=/data \
  ghcr.io/ykukmme/ros2-worker:jazzy \
  bash -c 'tail -n 100 /data/config/menu-logs/*.log'
```

| 로그 | 내용 |
|---|---|
| `commands.log` | 초기 설정·진단 명령의 상세 결과 |
| `calibration.log` | 초기 설정 중 인식·카메라 노드 |
| `live.log` | 실제 분류 서버의 시작·실행 기록 |

실행한 단계에 따라 일부 로그는 없을 수 있다. 다른 볼륨을 쓴다면 명령의 `src`를 실제 이름으로 바꾼다.
코드와 소프트웨어 경로는 검증했지만 실제 장비의 네트워크·집기 성공은 현장 확인이 필요하다.

## 보관되는 데이터

| 항목 | 컨테이너 내부 경로 |
|---|---|
| 교시·장비 설정 | `/data/config/live.local.yaml` |
| 현재 추론 장치에 맞춘 실행용 설정 | `/data/config/runtime.local.yaml` |
| 메뉴·노드 로그 | `/data/config/menu-logs/` |
| YOLO 사용자 설정 | `/data/ultralytics/` |

볼륨 이름은 `ros2-worker-data`다. 동일한 Docker 저장소와 볼륨을 사용하면 재실행·이미지 업데이트 후에도 유지된다.
PC를 바꾸면 자동으로 이동하지 않으며 볼륨을 삭제하면 설정도 사라진다.
공용 PC에 다른 장비의 설정을 보관할 때는 실행 전 `WORKER_VOLUME`에 별도 볼륨 이름을 지정한다.
파일 복사·기존 설정 이전은 [Docker 가이드](../DOCKER.md)와 [고급 설정](../ADVANCED_SETUP.md)을 따른다.

## Git 없이 실행기만 받기

Git이 없는 경우 3단계 대신 다음을 사용한다. curl이 없으면 브라우저로 같은 주소의 실행기를 `worker.sh`로 저장한다.

```bash
mkdir -p ~/ros2-worker-launcher
cd ~/ros2-worker-launcher
curl -fL https://raw.githubusercontent.com/ykukmme/ROS2_WORKER/codex/initial-release/scripts/run_worker.sh -o worker.sh
```

이 폴더에서 `bash worker.sh check`, `bash worker.sh`를 사용한다. 나머지 설정·실물 실행 순서는 같다.
다음 날에는 `cd ~/ros2-worker-launcher`로 이 폴더에 돌아온다.
업데이트할 때는 같은 URL에서 실행기를 다시 저장하고 `bash worker.sh update`를 실행한다. `git pull`은 사용하지 않는다.

## USB 오프라인 배포

이미지·실행기·`image.txt`·체크섬이 들어 있는 배포 폴더 전체를 받는다.
그 폴더에서 `bash worker.sh`를 실행하면 이미지가 없을 때 체크섬 확인 후 동봉 이미지를 등록한다.
이 경로는 온라인 Docker pull·Git clone 대신 사용한다. 로봇 준비·교시·분류 단계는 같다.
같은 태그의 새 USB 이미지를 등록할 때는 메뉴 종료 후 `bash worker.sh load`를 사용한다.
이전 실험의 `WORKER_IMAGE`가 지정돼 있다면 번들 기본 이미지를 쓸 때 `unset WORKER_IMAGE`로 해제한다.
세부 절차는 [오프라인 배포 안내](../DOCKER.md)를 따른다.
